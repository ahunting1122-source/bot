### A. ★ 最重要：`_source_conversations` 的折中**不可接受** —— 它是「静默漏数据」，不是「性能折中」

**你问的**：
> 「`_source_conversations` 先查 id 集合再过滤（不改 `browse()` 的 SQL 形状）——这是我为「少改坏」做的折中，但它意味着「筛 200 条里命中的那部分」，如果某来源的会话超过 200 条会漏。**你判这个折中可接受吗？**」

**我读了实现**（`app/cli/commands/sessions.py`）：
```python
:95   rows = context.run(context.store.rows(select(Conversation).where(Conversation.source == source)))
      return {row.id for row in rows}                    ← **这一步是正确的**：全量 SQL，无 limit ✓

:109  # 带 --workspace / --source 时必须先多取一些再过滤：
:110  # 直接 limit 会在过滤前就把命中切掉。
:111  fetch = 200 if (workspace or source) else limit
:112  sessions = _run(context, searcher.browse(limit=fetch))     ← 取最近 200 条（**未筛**）
:114  if source:
:115      allowed = _source_conversations(context, source)
:116      sessions = [item for item in sessions if item["id"] in allowed]   ← **在 200 条里筛** ✗
```

**所以答案是：不可接受** ✗ —— **理由不是"折中不够好"，是它错了类型**：

| 它是什么 | 它不是什么 |
|---|---|
| **静默漏数据** | ~~性能折中~~ |
| 用户查 `--source tool` 得到空列表 → **会以为"没有 tool 会话"**，而实际可能有 300 条 | 不是"慢一点" |

**三个具体问题**：

1. **`200` 是魔法数，任何"取更多"都只是把阈值推远**
   `fetch = 200` 换成 `2000` 不解决问题 —— **它只是把"第 201 条漏"改成"第 2001 条漏"**。
2. **`--workspace` 是**完全相同的模式**（`:119 _workspace_conversations` + 同一个 200 窗口）
   → **同一个 bug 出现两次**，而且**两处都静默**。
3. **你自己的注释已经承认了这个问题**
   > 「直接 limit 会在过滤前就把命中切掉。」
   **你看到了问题，然后用一个更大的常数把它盖住了。**

**正确做法（两个，都便宜）**：

**① 把条件推到 SQL（推荐）**
```python
# SessionSearch.browse 加一个可选参数
async def browse(self, *, limit=20, source: str = "") -> list[dict]:
    stmt = select(Conversation)
    if source:
        stmt = stmt.where(Conversation.source == source)     # ← 条件进 SQL
    ...
```
**为什么可行**：**`_source_conversations` 已经证明 `Conversation.source` 可以直接 `where`** —— 所以 `browse()` 里加同一个 `where` **不会牵动它的 SQL 形状**（这正是你担心的那点，而它不成立）。

**② 或者：直接用 id 集合去取会话**
```python
if source:
    allowed = _source_conversations(context, source)         # 全量 id，无 limit
    sessions = _run(context, searcher.browse_ids(allowed, limit=limit))
```
**成本略高于 ①，但同样消除魔法数。**

**判据**：
> **过滤条件的正确位置是「数据源」，不是「取回之后」。**
> **取回之后再筛，就必然有一个"取多少"的魔法数，而任何魔法数都会漏。**

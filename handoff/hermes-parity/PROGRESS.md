### A. `PathPolicy.allowed_roots` 语义 → ✅ 你的理解正确，我实测了 10 类输入

**先核语义**（你的问法很关键）：
```python
# path_security.py
:43   `allowed_roots` 为空时**不限制根**（其余四类检查照做）
:174  allowed_roots: tuple[Path, ...] = ()
:291  if self.allowed_roots:
:294      if not any(_within(resolved_form, root) for root in roots):  → 拒绝
```
→ **语义正是「解析后的路径必须落在某个根之下」** ✓ 与你的理解一致 ✓

**而 `_within` 的实现是对的**（这条我特意核了，因为朴素的 `startswith` 会有安全漏洞）：
```python
return child == root or child.startswith(root.rstrip("\\") + "\\")
```
→ **先补一个分隔符再比前缀** → `…/files-evil.txt` **不会**误判成 `…/files` 的子路径 ✓✓

**实测 10 类输入（`machine=False`）**：

| 输入 | 结果 | 判定 |
|---|---|---|
| 根内相对路径 `a.txt` | 通过 | ✅ |
| 根内子目录 `sub` | 通过 | ✅ |
| 根内绝对路径 | 通过 | ✅ |
| `./a.txt` | 通过 | ✅ |
| **根外绝对路径 `C:\Windows\system32\cmd.exe`** | **拒绝 `outside_root`** | ✅✅ |
| 根外绝对路径（临时目录里） | **拒绝 `outside_root`** | ✅✅ |
| 前缀相似 `../files-evil.txt` | 拒绝 `traversal` | ✅ |
| 设备命名空间 `\\.\C:\Windows` | 拒绝 `device_path` | ✅✅ |
| ADS `a.txt:stream` | 拒绝 `ads` | ✅✅ |
| **`sub/../a.txt`（解析后仍在根内）** | **拒绝 `traversal`** | ⚠️ **合法路径被拒** |

**→ 安全行为全部正确，只有一个故意的更严**：

> **任何含 `..` 的路径都被拒，即使解析后仍在根内。**

`PathPolicy` 的 `allow_dotdot` 默认 `False`，而 `resolve_path` **没有传它** → 走默认 → 拒绝消息自己也解释了理由：
> 「路径含上跳段（..）：**上跳之后的位置在解析前无法确认，所以默认拒绝**」

**我的判断**：**这个更严是对的**（拒绝在解析前发生，没有 TOCTOU 空间）**，但它改变了对外行为，必须写进证据栏**：
- **旧行为**：`../outside.txt` 被拒（因为结果在根外）；`sub/../a.txt` **通过**（因为结果在根内）
- **新行为**：**两者都被拒**（因为含 `..`）
→ **所以这是一次行为收紧，不只是"两份实现合一"** ✓ **你 docstring 里那句「这不是把检查搬个家」是对的，而且我实测证实了它确实更严。**

**建议**：证据栏补一句：「**新增拒绝：任何含 `..` 的路径（即使解析后仍在根内）**；代价 = 模型写 `sub/../a.txt` 这类合法路径会被拒。**理由：解析前无法确认上跳位置。**」

**现在详细说 3.1，因为那是你最担心的**：

**`default=allow` 跳过 IP 校验，是设计决定，不是洞。三条理由：**

**① 它的功能是「DNS rebinding 防护」，而 rebinding 的前提是「有 allow 规则被命中」**
```python
if not decision.rule:          # ← default=allow（没命中任何规则）→ 不查 IP
    return decision
```
**rebinding 攻击的模型是**：**一条 allow 规则放行了 `evil.com`，而 `evil.com` 解析到内网 IP** —— **没有 allow 规则时，就没有"放行"这个动作可被利用。** ✓

**② 唯一「无正当用途」的目标已经被单独硬拦了（第 51 轮，在 rule 匹配之前）**
**云元数据端点**（`169.254.169.254` / `metadata.google.internal`）**在 `check()` 里硬拦，不受 allow/deny 影响** ✓
→ **所以 `default=allow` 跳过的那部分里，剩下的全是「有正当用途的私网 IP」** ✓

**③ 而私网 IP 有正当用途 —— 改了会打死「配一个 provider 就能用」**
**本地 Ollama（`127.0.0.1:11434`）/ LM Studio（`localhost:1234`）/ 局域网 gateway（`192.168.1.50:8000`）** —— **这些是 Orbit 的核心用法** ✓
→ **如果 `default=allow` 也拦私网，那"开箱即用"就没了** ✗

**→ 结论：3.1 是设计决定 ✓，你把它写进「别碰」是对的。**

**而且更重要的一点**：**那个真正的残余洞（CNAME 到元数据 IP）并没有被这份文档豁免** ——
**它已经如实写在 `_refuse_cloud_metadata_endpoint` 的 docstring 里**（「通过 DNS 解析到元数据 IP 的域名挡不住…**已知残余风险**」）**并带了触发条件**（第 53 轮加的：「一旦 `base_url` 可来自不可信来源，或模型能影响请求 URL，就必须做解析」）✓

## 本轮抽查证据

**抽样率**：3 项点名**全部复核**；另**查了 Hermes 调研里 `--source` 的原始语义**（本轮最重要）。

### A. ★ 最重要：`--source` 接到了 `platform`，但 **Hermes 的 `--source` 是「会话来源标签，用于过滤」** —— 两个概念混了

**你的自问**：「`--source` 在 Hermes 侧是「会话来源标签」，我把它当 `platform` 用…**这是不是把两个概念混了？**我判断…是同一件事，**但这是我判断，不是实证**。」

**我去查了实证** —— `research/01-cli-surface.md:181`：
> 「`--source SOURCE` | 文本 | `cli` | **会话来源标签，用于过滤**。第三方集成可用 `tool`，**使其不出现在用户会话列表**」

**所以两个概念是不同的**：

| | Hermes `--source` | Orbit `platform`（6.4） |
|---|---|---|
| 作用 | **会话来源标签，用于过滤/隐藏** | **决定工具暴露面** |
| 消费者 | 会话列表 | `toolsets.resolve(platform=…)` |
| 典型值 | `cli` / **`tool`**（第三方集成，不出现在用户列表） | `cli` / `api` |

**而最直接的证据在你自己的代码里**：
```python
# chat.py:513  Option 的 help 原文
"会话来源标签（默认 cli），**用于按来源筛选**"
# chat.py:113  实际实现
await runner.enqueue(task.id, platform=getattr(context, "session_source", "") or "cli")
```
→ **help 说"用于按来源筛选"，实现却把它当 `platform`（决定工具暴露面）。** **help 与实现不一致。**

**而且我核了：Orbit 根本没有"会话来源"这个字段**
```
storage.py:193   source: Mapped[str] = mapped_column(String(160), default="local")
                 ↑ 这是 **Skill** 的 source（local / mcp:<服务>），**不是 Session/Conversation 的**
sessions 命令里**没有任何 --source 过滤选项**
```
→ **Hermes 的 `--source` 语义（隐藏第三方会话）在 Orbit 完全没实现** ✓

**所以 `--source` 从「零读取点」变成了「接到另一个概念上」—— 这是一个新变种**：
| 变种 | 例子 |
|---|---|
| 零读取点（装饰） | 原 `--run-budget` / 原 `--source` |
| **接到错误的概念上** | **现在的 `--source`** |
| 条件永不成立 | 4.3 的路由分支 |
| 接上了但消费者是坏的 | 4.9 的跨 provider 密钥 |

**后果**：第三方集成传 `--source tool`，期望**会话不出现在用户列表**；Orbit 实际做的是 `platform="tool"` → `platforms.tool` 没配置 → **工具集不变** → **会话仍然可见** → **净效果仍是 0，而且 help 在说谎。**

**建议（二选一，不能维持现状）**：
- **① 接对**：加 `Session.source` 字段 + `sessions list --source` 过滤（真做 Hermes 语义）。**量级约半天。**
- **② 标 🟢（有意差异）**：写明「Orbit 把 `--source` 用作 `platform`（决定工具暴露面），**不复现 Hermes 的"隐藏第三方会话"语义**」+ **代价**（第三方集成无法隐藏自己的会话），**并同步改 Option 的 help**。

**不能做的**：**维持 ✅ + 现在的 help** —— **因为 help 在承诺一个没实现的行为**，这正是第 23 轮那条「提示不能指向不存在的操作」的同族（只不过这次是 `--help` 文本）。

insights（对齐 hermes insights --days/--source）：
- token 三路归因分开记：工具读来的 / 模型自报的 / 摘要另起一次调用花的
- 工具排行、站点排行、每日活动；成功率只算终态任务
- 口径修正：失败数取自 tool_results.status（ok/error），不是 tool_calls.status
  （DONE/RUNNING）。第一版取错，把 97 次调用全算成失败——"失败率 100%"看起来像真的
- --source 是刻意的语义分歧：Hermes 用它区分平台，Orbit 单用户本地部署没有平台维度，
  落到"任务主要操作过哪个站点"这个真实维度上，而不是照抄一个永远为空的参数

monitoring status：
- 健康指标（库大小/完整性/页数/未终结任务/检查点库）+ 导出配置 + 脱敏姿态
- content-free by construction：不采集 prompt/消息/工具参数与结果，测试断言导出物
  里不含消息或结果正文

修 CLI 异步桥（真缺陷，被新测试打出来的）：
- 原来用 asyncio.run/run_until_complete：① 一条命令里第二次查询会撞上已关闭的循环
  ② main() 被异步宿主调用时（测试、将来的 API 端点）直接抛 "Cannot run the event
  loop while another loop is running"，且协程已创建却永不 await，只留一条 RuntimeWarning
- 改成固定用"一条专用线程 + 一个常驻循环"（run_coroutine_threadsafe），同步/异步
  上下文行为一致，Store 连接始终活在同一个循环上；close() 先 dispose 引擎再停循环再
  join 线程（顺序反了会数据竞争）

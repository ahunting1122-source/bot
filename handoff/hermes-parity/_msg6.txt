feat(logging): 结构化日志 + 按大小轮转 + 任务上下文（W12）

Orbit 之前**一条日志都没落过盘**：各模块都写了 logging.getLogger("orbit.xxx")，
但从来没配置过任何 handler，消息全靠 lastResort 打到 stderr，data/*.log 一直是 0 字节。
"出问题想查日志时日志不存在"——这不是小瑕疵，一个没有日志的常驻服务排障只能靠复现。

- app/logging_setup.py：
  · 行格式 `时间 级别 [task=<id>] 模块: 消息`（照 Hermes 形状，把 task 放进上下文）
  · task 上下文用 contextvars 而不是全局变量：asyncio 下多任务并发，全局变量会把
    A 任务的日志标成 B 任务的
  · 主日志 5MB × 5 份按大小轮转（不按天：一天里出 2GB 异常日志会写满盘）
  · errors.log 只收 WARNING 以上（出事第一眼看它，不用在几万行 INFO 里翻）
  · configure() 幂等：重配时精确摘掉自己装的 handler，不动别人的；不幂等的话测试里
    每个用例配一次会挂上几百个 handler，还会往已删除的临时目录写文件
- app/main.py：lifespan 第一件事就装日志（启动阶段的失败恰恰是"没有日志可查"的那一段），
  并补上本模块的 logger（此前 main.py 一条日志都没有）
- app/config.py：补 log_level / approval_mode / hardline_in_machine 三个字段
  （后两个原先只存在于 settings.json 的兜底读取里，没有 .env 支持）
- core.py 的 _log_files 同时扫 data/ 与 data/logs/（迁移期两处并存）

测试 7 条：两个文件都真的被写 / errors.log 只收 WARNING+ / task 上下文打进行里 /
上下文正确恢复 / configure 幂等 / 重配后输出换目录且不再写旧目录 / reset 摘干净
